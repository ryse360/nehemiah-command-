Nehemiah role (per MASTER_AI_HANDOFF §12 toolchain):
The build-and-verify discipline layer. Superpowers governs HOW work is done
once a decision is made — brainstorming before implementation, written plans,
test-driven development, systematic debugging, worktree isolation, code
review, and verification before any completion claim.

Governing sequence (from the handoff):
  ADHD widens the field.
  Nehemiah governs the decision.
  Superpowers builds and verifies the winner.

Vendored skills:
- brainstorming — structured divergence/convergence before writing code
- writing-plans / executing-plans — durable implementation plans
- test-driven-development — red/green/refactor, watch the test fail first
- systematic-debugging — root-cause discipline for fuzzy bugs
- using-git-worktrees — isolated worktree workflow
- requesting-code-review / receiving-code-review — review loop
- verification-before-completion — evidence before "done"
- dispatching-parallel-agents / subagent-driven-development — fan-out work
- finishing-a-development-branch — clean branch close-out
- using-superpowers / writing-skills — meta

Governance:
Use for consequential build work. Do not ceremonially invoke on trivial
mechanical edits. Superpowers does not redefine product purpose, Founder-
locked decisions, or MiP worldview — it is process discipline only.
