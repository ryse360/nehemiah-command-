# Nehemiah Command v0.15.0 — Founder Authentication

## Outcome

Nehemiah now requires a private Founder session before rendering the command interface or allowing cloud memory access.

## Controls

- Founder passphrase verification using timing-safe comparison.
- Signed, expiring session token stored in an HttpOnly, SameSite=Strict cookie.
- Secure cookie enforcement in production.
- Server-rendered sign-in gate for the root application.
- Session-protected Founder memory GET and PUT routes.
- Explicit logout that invalidates the browser session.
- Recovery-preparation endpoint with non-enumerating language.
- Manual cloud access-key prompts removed from the Founder experience.

## Configuration

- `NEHEMIAH_FOUNDER_PASSWORD`
- `NEHEMIAH_SESSION_SECRET`
- `NEHEMIAH_SESSION_TTL_SECONDS`
- `NEHEMIAH_FOUNDER_ID`

## Security boundary

This release provides single-Founder authentication and secure browser sessions. Multi-device management, credential rotation UI, rate limiting, recovery-code issuance, MFA, and role-based authorization remain future security milestones.
