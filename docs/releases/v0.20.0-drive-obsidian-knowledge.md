# Nehemiah Command v0.20.0 — Drive and Obsidian Knowledge Integration

## Purpose

Give Nehemiah governed access to source material from Google Drive and Obsidian while preserving provenance, visibility boundaries, and Founder authority.

## Delivered

- Google Drive knowledge ingestion route.
- Obsidian note ingestion route.
- Bounded source normalization and validation.
- Separate `knowledge_sources` PostgreSQL table and migration 005.
- Controlled upsert behavior that rejects stale provider versions.
- Founder-only source index and search API.
- Lightweight relevance ranking with grounded excerpts and citations.
- Founder Knowledge interface with source visibility, timestamps, tags, references, and citations.
- Security audit events for every accepted source synchronization.
- Production integration contract for Google Drive and Obsidian bridges.

## Governance

- Integrations append or synchronize source records only.
- They cannot read Founder-private memory or approve decisions.
- `founder-private` records are visible only through authenticated Founder retrieval.
- Enterprise-only retrieval can exclude Founder-private material.
- Source content is capped at 4,000 characters per record in this release.
- Search is deterministic and local to the stored source index; semantic embeddings are not introduced yet.

## Operational requirements

- Apply `docs/database/005-drive-obsidian-knowledge.sql`.
- Configure rotating keys for `google-drive` and `obsidian`.
- Connect approved provider bridges with least-privilege access.
- Confirm authorized vault paths and Drive folders before initial synchronization.
