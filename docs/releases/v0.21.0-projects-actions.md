# Nehemiah Command v0.21.0 — Projects and Actions Integration

## Purpose

Turn approved Founder decisions into governed enterprise execution records with explicit ownership, dependencies, deadlines, blockers, progress, and visible proof.

## Delivered

- Founder-only Projects and Actions API inside the enterprise data boundary.
- Project and action validation for ownership, status, dates, progress, dependencies, blockers, and proof.
- Portfolio summary showing active projects, open actions, blocked actions, overdue actions, and completed actions.
- Founder-attention queue that prioritizes blocked work before overdue work.
- Optimistic revision control through the existing enterprise-context persistence boundary.
- Project workspace in the private Founder interface.
- Status and progress updates from the governed workspace.
- Visible proof intake attached to the exact action that produced it.
- Enforcement preventing an action from being marked complete before proof exists.
- Legacy enterprise-project normalization so earlier project records remain readable.

## Governance

- Project records live in the enterprise domain, not Founder-private memory.
- Only an authenticated Founder session may read or update the portfolio in this release.
- Approval is not treated as execution, and progress is not treated as proof.
- Completion requires at least one preserved visible-proof record.
- Stale revisions are rejected rather than overwriting newer project state.
- Nehemiah does not autonomously reassign owners, change deadlines, or close actions.

## Persistence

This milestone uses the existing `enterprise_context` PostgreSQL record introduced in migration 002. No new database migration is required. Projects are stored as versioned JSON inside the enterprise context and protected by the existing optimistic revision check.

## Verification target

- Project validation and immutable update behavior.
- Proof-before-completion enforcement.
- Blocked and overdue attention ordering.
- Authenticated API compilation.
- Strict TypeScript and optimized production build.
