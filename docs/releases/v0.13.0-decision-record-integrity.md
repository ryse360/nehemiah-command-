# Nehemiah Command v0.13.0 — Decision Record Integrity

## Purpose

Preserve Founder decisions as versioned, tamper-evident records whose provenance and material changes can be inspected without overwriting prior history.

## Delivered

- Founder memory schema upgraded from version 1 to version 2.
- Every completed decision is archived as record version 1.
- Each record preserves journey provenance from command through proof.
- Each record includes a chained audit trail with actor, reason, timestamp, prior hash, record digest, and event hash.
- Material corrections create a new version rather than replacing the prior record.
- Revisions require a specific reason and an actual material change.
- Record integrity verification detects changed decision content or broken audit links.
- Existing browser memory using the v1 schema migrates into the v2 integrity ledger.
- Founder Memory displays record version, integrity status, provenance count, and audit history.

## Governance boundary

This release provides an append-only application model and local tamper-evidence. It does not yet provide server-enforced immutability, cryptographic signing by a trusted service, or external notarization. Those controls belong to cloud persistence and security hardening milestones.

## Acceptance criteria

- A completed decision produces one versioned record and one genesis audit event.
- Any material change to the current record causes integrity verification to fail.
- A valid correction produces a new record version while retaining the prior version unchanged.
- Empty reasons and non-material revisions are rejected.
- Legacy v1 records migrate without data loss.
