# Founder Decision Journey v0.4.0

## Release purpose

Turn the Phase 1 visual prototype into the first governed Nehemiah behavior loop.

## Founder journey

1. Founder submits a consequential command.
2. Nehemiah enters Listening.
3. Nehemiah surfaces the priority and why it comes first.
4. Nehemiah prepares the Founder-only decision.
5. Founder approves, approves with limits, requests evidence, delays, or rejects.
6. Approved decisions create a visible action record.
7. The journey cannot complete until proof is captured.
8. Closing the review returns Nehemiah to Resting while preserving history in the journey model.

## Governance rules implemented

- No lifecycle state can be bypassed through the production interface.
- Founder decision authority remains explicit.
- Approval is not treated as completion.
- Visible action must precede proof.
- Requesting evidence or delaying returns the decision to focus rather than falsely advancing execution.
- Rejection is preserved as valid decision proof.
