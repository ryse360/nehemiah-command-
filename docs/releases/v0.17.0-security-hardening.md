# Nehemiah Command v0.17.0 — Security Hardening

## Release purpose

Strengthen the Founder authentication and integration perimeter before live AI and external integrations are enabled.

## Delivered controls

- Founder passphrases are verified against salted scrypt hashes; plaintext password configuration is removed.
- Founder session tokens carry unique session IDs and an authentication version.
- Logout revokes the active session server-side.
- Incrementing `NEHEMIAH_AUTH_VERSION` invalidates all previously issued sessions.
- Login attempts are rate limited and return `429` with `Retry-After`.
- Integration ingestion is rate limited separately.
- Integration keys support a current key plus a time-bounded previous key for safe rotation.
- Authentication, logout, rate-limit, and integration events are written to a redacted security audit stream.
- Security headers restrict framing, referrers, content types, browser capabilities, and cross-origin behavior.
- PostgreSQL migration adds revoked-session and security-audit tables.
- Backup/recovery and incident-response runbooks define containment and proof requirements.

## Deployment requirements

1. Run `docs/database/003-security-hardening.sql`.
2. Generate the Founder password hash:

```bash
npm run security:hash-password -- "a private passphrase of at least 16 characters"
```

3. Store the output as `NEHEMIAH_FOUNDER_PASSWORD_HASH`.
4. Set a random `NEHEMIAH_SESSION_SECRET` of at least 32 bytes.
5. Set `NEHEMIAH_AUTH_VERSION=1`; increment it during emergency global session revocation.
6. Configure rotating integration keys using the structure in `.env.example`.

## Security boundary

The included in-process rate limiter protects a single application instance. A shared Redis or database-backed limiter is still required before horizontally scaled public deployment. Database backups must be configured at the infrastructure provider; this repository defines the control and rehearsal procedure but cannot provision provider credentials by itself.
