# Nehemiah Command v0.14.0 — Cloud Persistence

## Outcome

Founder memory can now move beyond browser-only storage into a private PostgreSQL database through an authenticated server API.

## Included

- PostgreSQL-backed Founder memory store.
- Durable JSONB storage for the complete integrity ledger.
- Optimistic concurrency through revision numbers.
- Conflict rejection for stale writes.
- Local/cloud merge without duplicate record versions.
- Authenticated GET and PUT API endpoints.
- Founder session access key held in session storage, never local storage.
- Database migration SQL and deployment environment template.
- Local-first fallback when cloud credentials are absent.

## Required deployment configuration

1. Provision a private PostgreSQL database.
2. Run `docs/database/001-founder-memory.sql`.
3. Set `DATABASE_URL`.
4. Set `NEHEMIAH_FOUNDER_ID`.
5. Set a long random `NEHEMIAH_FOUNDER_ACCESS_KEY`.

## Security boundary

This milestone protects the API with a Founder access key and keeps the database server-side. Full identity, session recovery, device governance, and authorization policies remain scheduled for v0.15–v0.17.
