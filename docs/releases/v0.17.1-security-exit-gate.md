# v0.17.1 — Security Exit Gate

## Purpose

Close the remaining application-level security gaps before live AI orchestration.

## Completed

- Replaced process-local login and integration rate limiting with a shared store abstraction.
- Added a PostgreSQL-backed distributed rate-limit adapter for multi-instance deployments.
- Added migration `004-security-exit-gate.sql`.
- Added production secret and migration readiness checks.
- Added encrypted backup-manifest and restore-rehearsal verification tooling.
- Added dependency-advisory handling policy that rejects unsafe forced downgrades.
- Added tests for distributed rate limiting, deployment readiness, and backup verification.

## Deployment boundary

The shared limiter becomes operational after migration 004 is applied to the configured PostgreSQL database. Without `DATABASE_URL`, development uses an in-memory fallback only.

Actual backup scheduling, production secret installation, and a live restore rehearsal require the deployment environment and cannot be truthfully completed inside the source-only runtime.
